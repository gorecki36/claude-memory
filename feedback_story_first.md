For any content deliverable (deck, essay, web page, carousel, brief, visual), work in two gated phases: (1) STORY as tight bullets, signed off by Vas; (2) PRESENTATION built only after approval. Never deliver substance and polished artifact in one pass.

**Why:** On the ai-economics Chapter 2 build (2026-06-06), I jumped straight from concept to a full polished HTML page. Vas: "this is verbose and flaky... we need substance... the first thing we should do is to bullet point the story together. then we go to presentation. you did all in one go and it got off." One-shotting both lets the narrative drift and reads as flaky.

**How to apply:** When asked to "draft it" / "build the deck" / "write the essay" / "another chapter", default to Phase 1 bullets first (spine, ordered beats with claim+evidence, key data listed once, close), stop, get sign-off, then build. The story gate is the task boundary, not a quitting point. This refines [[feedback_dont_stop_midtask]] (which is about mechanical end-to-end work) and pairs with [[feedback_carousel_process]] (lead with an opinionated spine). Codified as the `story-first` skill at ~/.claude/skills/story-first/.
